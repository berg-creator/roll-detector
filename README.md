# roll-detector

Детектор роликов картона на выходе транспортера и управляющая программа с виртуальным реле.

## Задача
1. По видео `demo_1..8.mp4` обучить детектор роликов картона (один класс, каждый ролик своей рамкой).
2. Программа на Python, камера 20 fps:
   - ролик в зоне выхода транспортера (левее X) держится Y секунд -> реле блокируется;
   - в зоне нет ролика дольше Z секунд -> реле разблокируется.

## Запуск
Веса и видео в git не лежат. Модель есть в релизе v1.0: `roll_yolo11n.pt` и
`roll_yolo11n_openvino_model.zip` (распаковать) положить в `models/`. Видео - в `data/videos/`.

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu

# на записи (кадры берутся с частотой камеры, 20 fps)
python src/run.py --source data/videos/demo_4.mp4 --save out.mp4 --events events.csv
# камера / поток
python src/run.py --source 0
python src/run.py --source rtsp://10.0.0.5/stream
# свои X, Y, Z
python src/run.py --source data/videos/demo_1.mp4 --x 0.4 --y 3 --z 5

pytest
```

Все параметры (модель, зона, таймеры, камера) в `config.yaml`.

## Обучение
Разметка уже лежит в `data/labels/`, DINO заново гонять не нужно.
```bash
python tools/extract_frames.py --step 12           # 404 кадра в data/frames
python tools/make_labels.py --val demo_4 demo_6    # датасет в data/dataset
python tools/review.py                             # листы для проверки
python src/train.py                                # ~1.5 ч на 2 vCPU, в конце экспорт в OpenVINO
python tools/eval_zone.py --weights models/roll_yolo11n.pt
```

### Данные
Видео 1280x720, 60 fps, всего около 7000 кадров. Брал каждый 12-й, кадры где сцена не меняется
прореживал, получилось 404 кадра.

Черновую разметку сделал Grounding DINO (zero-shot, запрос "a cardboard roll"), потом фильтр
в `make_labels.py` и проверка всех кадров глазами. Что пришлось исправлять:
- рамка на всю площадку - выкидываю всё шире 500 px;
- ролики, которые еще наполовину в машине у левого края, DINO не видел. Камера неподвижная,
  поэтому рамки для них получил вычитанием пустого кадра того же видео;
- стопку плоских листов картона у стены (demo_8) принимал за ролик - эту область исключил;
- складские ролики у дальней стены находил через раз - сделал для них постоянные рамки;
- 3 кадра, где непонятно, ролик там или нет, убрал из датасета.

Дальше обучил модель на этой разметке и прогнал ее по всем кадрам (`compare_labels.py`).
Она нашла ролики, пропущенные при разметке, например ролик в тени внутри машины перед выходом.
Все расхождения просмотрел, исправил 29 кадров, обучил заново. Третий такой проход нашел еще
9 кадров с плохо видным роликом у края, после них обучил финальную модель.

Train/val делил по видео (val: demo_4, demo_6). Соседние кадры одного видео почти одинаковые,
если делить случайно, метрики будут завышены.

### Модель
YOLO11n с весами COCO, дообучена на одном классе `roll`, вход 480 px. Взял самую маленькую
из-за CPU: на 20 fps бюджет 50 мс на кадр, а PyTorch на 2 vCPU в него не влезает (~55 мс).
Поэтому для работы модель экспортирована в OpenVINO - примерно вдвое быстрее, результаты те же.
При старте модель прогревается пустым кадром, чтобы первый кадр с камеры не тормозил.

## Логика

**Зона** - прямоугольник в долях кадра: по x от 0 до X, по y от `y_min` до `y_max`.
Ограничение по высоте нужно, потому что складские ролики у дальней стены тоже левее X.
Ролик считается в зоне, если в нее попадает не меньше 25% площади его рамки.

**Реле** (`relay.py`) - два состояния:
- разблокировано -> заблокировано, когда ролик в зоне непрерывно Y секунд;
- заблокировано -> разблокировано, когда зона пустая Z секунд.

Детали:
- время берется из меток кадров, а не из счетчика, так что пропуски кадров и плавающий fps
  таймеры не ломают;
- если детектор потерял ролик на кадр-два (до 0.3 с, `gap_tolerance`), отсчет Y не сбрасывается;
- для разблокировки наоборот: любое появление ролика заново запускает отсчет Z. Лишний раз
  постоять лучше, чем отправить ролик в занятую зону;
- при старте реле заблокировано, пока зона не будет пустой Z секунд. Если камера молчит дольше
  `timeout` или обработка кадра упала, реле тоже блокируется;
- с камеры берется самый свежий кадр, без очереди, чтобы решение не отставало,
  если обработка медленнее камеры.

## Результаты

Детектор на val (demo_4 + demo_6, эти видео модель не видела; 80 кадров, 240 рамок):

| | Precision | Recall | mAP50 | mAP50-95 |
|---|---|---|---|---|
| PyTorch (`.pt`) | 0.999 | 0.996 | 0.995 | 0.978 |
| OpenVINO | 0.999 | 1.000 | 0.995 | 0.971 |

Решение "ролик в зоне" по кадрам (`eval_zone.py`, conf 0.5, 401 кадр): из 97 кадров с роликом
в зоне пропущено 0, ложных срабатываний на пустой зоне нет. Расхождений с разметкой 6
(train 5, val 1), все одинаковые: модель видит ролик на один кадр выборки (0.2 с) раньше
разметки, когда из машины торчит только темный торец 15-20 px. Если увеличить, видно, что он
уже закрывает трос, который на пустом кадре доходит до края, то есть ролик там правда есть.

Вся система на 8 видео (20 fps, X=0.4, Y=3 с, Z=5 с). Ролик в зоне виден одним интервалом
3.65-4.1 с без разрывов, моменты переключения проверял по кадрам:

| видео | длина | ролик в зоне, с | реле |
|---|---|---|---|
| demo_1 | 10 с | - | блок. 0 -> разблок. 5.0 |
| demo_2 | 20 с | 0-1.45; 9.2-13.25 | блок. 0 -> разблок. 6.45 -> блок. 12.2 -> разблок. 18.25 |
| demo_3 | 20 с | 6.7-10.45 | блок. 0 -> разблок. 5.0 -> блок. 9.7 -> разблок. 15.45 |
| demo_4 | 20 с | 0-2.45; 10.35-14.2 | блок. 0 -> разблок. 7.45 -> блок. 13.35 -> разблок. 19.2 |
| demo_5 | 20 с | 6.95-11.05 | блок. 0 -> разблок. 5.0 -> блок. 9.95 -> разблок. 16.05 |
| demo_6 | 5 с | - | блок. 0 (видео короче Z) |
| demo_7 | 1.7 с | - | блок. 0 (видео короче Z) |
| demo_8 | 20 с | 2.15-5.8; 13.8-17.45 | блок. 0 -> разблок. 10.8 -> блок. 16.8 |

При conf 0.4 / 0.5 / 0.6 разблокировки совпадают, блокировка сдвигается максимум на 0.2 с.
PyTorch и OpenVINO дают одинаковые события на всех 8 видео.

Скорость на 2 vCPU (AMD EPYC): OpenVINO в среднем 26-35 мс на кадр (28-38 fps при нужных 20),
PyTorch 55 мс. Около 5% кадров дольше 50 мс - параллельно работали другие процессы. Задержка
не накапливается, потому что всегда берется свежий кадр.

## Ограничения
- Данных мало: 8 коротких видео с одной камеры при одном освещении. Перед запуском на объекте
  надо добрать кадры в другие смены и при другом свете и дообучить.
- X, `y_min` и таймеры подбираются на месте под реальное положение выхода.
- Виртуальное реле на объекте меняется на запись в ПЛК (Modbus/OPC UA) или дискретный выход.
  ПЛК должен сам блокировать транспортер при потере связи (heartbeat), иначе при зависании
  программы реле останется в последнем состоянии.
- Пропажу кадров программа ловит (блокировка по `timeout`), а плохие кадры нет: если камеру
  закроют или она начнет отдавать черный или замерший кадр, программа увидит пустую зону.
  Нужна отдельная проверка кадра (яркость, изменения между кадрами).
