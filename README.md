# Roll detector

Детектор роликов картона на выходе транспортёра и управляющая программа
виртуального реле.

## Задание
1. На видео (`data/videos/demo_1..8.mp4`) обучить одноклассовый детектор роликов картона.
   Каждый ролик — отдельная прямоугольная рамка.
2. Управляющая программа на Python (реальное время, камера 20 fps):
   - ролик в зоне выхода из транспортёра левее X (относительно кадра) в течение Y с → блокировка виртуального реле;
   - ролика нет в зоне дольше Z с → реле разблокируется.

## Быстрый старт
Веса и видео в git не хранятся (большие бинарные файлы). Перед запуском:
- обученная модель из релиза v1.0 — `roll_yolo11n.pt` и распакованный `roll_yolo11n_openvino_model.zip` — в `models/`;
- исходные записи `demo_1..8.mp4` — в `data/videos/`.

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu

# прогон на записи (кадры берутся с частотой камеры, 20 fps)
python src/run.py --source data/videos/demo_4.mp4 --save out.mp4 --events events.csv
# живая камера / поток
python src/run.py --source 0
python src/run.py --source rtsp://10.0.0.5/stream
# свои X, Y, Z
python src/run.py --source data/videos/demo_1.mp4 --x 0.4 --y 3 --z 5

pytest            # тесты логики реле и зоны
```

## Структура
```

  relay.py             логика блокировки (конечный автомат, таймеры Y/Z), без CV
  zone.py              геометрия зоны и проверка «ролик в зоне»
  detector.py          обёртка над YOLO
  sources.py           видеофайл / живая камера (поток чтения, watchdog)
  train.py             дообучение YOLO11n
tools/
  extract_frames.py    нарезка кадров из видео
  autolabel.py         черновая авторазметка (Grounding DINO, zero-shot)
  make_labels.py       фильтрация черновика, ручные правки, YOLO-датасет
  review.py            контрольные листы для проверки разметки глазами
  compare_labels.py    сверка разметки с предсказаниями модели (второй проход)
  eval_zone.py         оценка на уровне задачи: «есть ли ролик в зоне» по кадрам

  boxes.json           итоговая разметка (пиксели)

```

## Воспроизведение обучения
Черновая и итоговая разметка лежат в `data/labels/`, поэтому Grounding DINO заново запускать не нужно.
```bash
python tools/extract_frames.py --step 12           # кадры -> data/frames (404 шт.)
python tools/make_labels.py --val demo_4 demo_6    # разметка + правки -> data/dataset (YOLO)
python tools/review.py                             # контрольные листы для проверки глазами
python src/train.py                                # обучение + экспорт в OpenVINO, ~1.5 ч на 2 vCPU
python tools/eval_zone.py --weights models/roll_yolo11n.pt   # оценка «ролик в зоне»
```

## Как устроено

### Данные и разметка
- Из 8 видео (1280×720, 60 fps, 7000 кадров) взят каждый 12-й кадр, почти одинаковые
  кадры статичной сцены прорежены — 404 кадра.
- Черновую разметку сделал zero-shot детектор Grounding DINO (запрос «a cardboard roll»).
  Черновик отфильтрован правилами (`make_labels.py`) и проверен глазами по всем кадрам.
  Найденные систематические ошибки и их исправление:
  - рамка «вся площадка» — отбрасываются рамки шире 500 px;
  - ролики, частично скрытые в машине у левого края кадра (выход транспортёра), не находились —
    рамки получены вычитанием пустого кадра того же видео (камера неподвижна);
  - стопка плоских листов картона у стены (demo_8) принималась за ролик — область исключена;
  - складские ролики у дальней стены находились нестабильно — заданы постоянными рамками;
  - кадры, где нельзя уверенно сказать «ролик» или «фон», исключены (3 кадра).
- Второй проход: модель, обученная на первой версии разметки, прогнана по всем кадрам
  (`compare_labels.py`). Она нашла ролики, которые пропустили и автомат, и проверка:
  ролик в тени внутри машины, ждущий выхода. Все расхождения просмотрены, 29 кадров исправлено,
  после чего модель обучена заново. Третий такой проход нашёл ещё 9 кадров с плохо видимым
  роликом у края; после их исправления модель обучена в последний раз.
- Train/val разделены **по видео** (val = demo_4, demo_6), а не по кадрам:
  соседние кадры одного видео почти одинаковы, случайное деление завысило бы метрики.

### Детектор
YOLO11n, предобученный на COCO, дообучен на одном классе `roll`, вход 480 px.
Маленькая модель выбрана из-за требования реального времени на CPU: 20 fps дают
бюджет 50 мс на кадр. В PyTorch модель на 2 vCPU в него не укладывается, поэтому
для работы она экспортирована в OpenVINO: вдвое быстрее, решения те же (см. «Результаты»).
При запуске модель прогревается пустым кадром, чтобы первый кадр с камеры не был медленным.

### Зона
Прямоугольник в долях кадра: `x ∈ [0, X]`, `y ∈ [y_min, y_max]`.
Ограничение по высоте нужно, потому что складские ролики у дальней стены тоже
находятся левее X. Ролик считается в зоне, если в ней лежит ≥ 25 % площади его рамки.

### Логика реле (`relay.py`)
Конечный автомат с двумя состояниями:
- `UNLOCKED → LOCKED`: ролик в зоне непрерывно `Y` секунд;
- `LOCKED → UNLOCKED`: зона пуста `Z` секунд.

Решения, важные для работы на объекте:
- **Время берётся из меток кадров**, а не из счётчика кадров: при пропуске кадров
  или переменном fps таймеры остаются верными.
- **Короткие пропуски детекции** (≤ `gap_tolerance`, 0.3 с) не сбрасывают отсчёт `Y`:
  детектор может потерять ролик на кадр-два (блик, захват погрузчика).
- **Для разблокировки пропуски не прощаются**: любое появление ролика перезапускает `Z`.
  Ошибка в эту сторону безопаснее.
- **Безопасное состояние — блокировка**: при старте реле заблокировано, пока зона не будет
  пуста `Z` секунд; если камера молчит дольше `timeout` или обработка кадра упала —
  аварийная блокировка.
- **Свежий кадр, а не очередь**: живая камера читается в отдельном потоке, обработка берёт
  последний кадр. Если обработка медленнее камеры, решение не отстаёт от реальности.

## Результаты

**Детектор** (val = demo_4 + demo_6, видео, которых модель не видела; 80 кадров, 240 рамок):

| | Precision | Recall | mAP50 | mAP50-95 |
|---|---|---|---|---|
| PyTorch (`.pt`) | 0.999 | 0.996 | 0.995 | 0.978 |
| OpenVINO | 0.999 | 1.000 | 0.995 | 0.971 |

**Решение «ролик в зоне» по кадрам** (`eval_zone.py`, conf 0.5, 401 кадр): пропусков 0
из 97 кадров с роликом в зоне. Расхождений с разметкой 6 (train 5, val 1), и все они одного
вида: модель видит ролик на один кадр выборки (0.2 с) раньше разметки — когда из машины
показался только тёмный торец шириной 15–20 px. При увеличении видно, что он уже закрывает
трос, который на пустом кадре того же видео доходит до края, т. е. ролик там действительно есть.
Ложных срабатываний на пустой зоне нет.

**Вся система на 8 видео** (20 fps, X=0.4, Y=3 с, Z=5 с). Ролик в зоне виден одним
непрерывным интервалом 3.65–4.1 с, без дробления; моменты переключения реле проверены по кадрам:

| видео | длительность | ролик в зоне, с | реле |
|---|---|---|---|
| demo_1 | 10 с | — | блок. 0 → разблок. 5.0 |
| demo_2 | 20 с | 0–1.45; 9.2–13.25 | блок. 0 → разблок. 6.45 → блок. 12.2 → разблок. 18.25 |
| demo_3 | 20 с | 6.7–10.45 | блок. 0 → разблок. 5.0 → блок. 9.7 → разблок. 15.45 |
| demo_4 | 20 с | 0–2.45; 10.35–14.2 | блок. 0 → разблок. 7.45 → блок. 13.35 → разблок. 19.2 |
| demo_5 | 20 с | 6.95–11.05 | блок. 0 → разблок. 5.0 → блок. 9.95 → разблок. 16.05 |
| demo_6 | 5 с | — | блок. 0 (видео короче Z) |
| demo_7 | 1.7 с | — | блок. 0 (видео короче Z) |
| demo_8 | 20 с | 2.15–5.8; 13.8–17.45 | блок. 0 → разблок. 10.8 → блок. 16.8 |

**Устойчивость к порогу:** при conf 0.4 / 0.5 / 0.6 моменты разблокировки совпадают,
блокировка сдвигается не более чем на 0.2 с. PyTorch и OpenVINO дают одинаковые события
на всех 8 видео.

**Скорость** (2 vCPU AMD EPYC): OpenVINO — в среднем 26–35 мс на кадр (28–38 кадр/с
при нужных 20), PyTorch в тех же условиях — 55 мс. Отдельные кадры (5 %) обрабатываются дольше
50 мс — на машине параллельно работали другие процессы; задержка от этого не копится,
потому что обработка всегда берёт свежий кадр с камеры.

## Ограничения и что делать на объекте
- Данных мало: 8 коротких видео одной камеры при одном освещении. Перед запуском — дособрать
  кадры в другие смены/освещение и дообучить.
- X, `y_min` и таймеры подбираются на месте по реальному положению выхода транспортёра.
- Виртуальное реле заменяется записью в ПЛК (Modbus/OPC UA) или дискретный выход;
  ПЛК должен сам блокировать транспортёр при потере связи (heartbeat), иначе зависание
  программы оставит реле в последнем состоянии.
- Пропажа кадров ловится (аварийная блокировка через `timeout`), а «плохие» кадры — нет:
  если камеру закроют или она начнёт отдавать чёрный/замёрзший кадр, программа увидит
  пустую зону. На объекте стоит добавить проверку кадра (яркость, изменение между кадрами).
